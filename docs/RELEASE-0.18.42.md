# 0.18.42：回执会自己过期，使用次数说真话

## 问题

- 回执（最近操作记录）只在「接受候选」时清过期项。不产候选的层会一直留着过期回执，
  状态文件只增不减；`receipts` 上限 256 条，过期数据还可能把新回执挤掉。
- 记录里的 `hits` 字段从来没人加：写的时候是 0，之后一直是 0，既占状态字节又不反映
  真实使用，面板也没法解释「这条被用过几次」。

## 改法

- 抽出 `pruneReceiptList(rows, now)`：按 7 天 TTL 过滤并截到上限。每次状态写入
  （`applyFlat`）顺手调用，不再依赖候选审批；`pruneReceipts` 改为复用同一函数。
- `hits` 改为「真实交付并记账的回合数」：只有 `markUsed` / 回合收尾记账才加一；
  检索、阅读、注入正文仍是纯读，不碰 `hits`，只在需要时补 `lastUsed`。
- `everUsed` 与 `lastUsed` 的写入合并进同一次保存判断：第一次被用到时标记一定落盘，
  十分钟防抖只约束 `lastUsed` 的重复回写。
- 没有新增常驻提示、没有改召回顺序与注入字节，状态只减不增。

## 验证

- `test/store.test.mjs`：预置一条过期、一条新鲜回执，任意一次普通写入后过期项被清掉。
- `test/store.test.mjs`：检索/阅读后 `hits` 不变、`lastUsed` 不变。
- `test/recall.test.mjs`：送达记账后 `hits === 1`，再次记账累加到 2，不受防抖影响。
- `test/contract.test.mjs`：注入正文本身不写 `hits`；交付过的卡片在下一轮开头记一次。
- 全量 `npm test` 通过。
