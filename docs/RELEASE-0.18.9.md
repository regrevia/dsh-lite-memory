# 0.18.9：句柄统一用标题，召回排序更认「两个概念都落在标题」

## 为什么会话里反复去翻 state.json 找编号

更新一条记忆（`updateTitle`）、关联两条记忆（`links[].title`）、绑定同一主题（`sameTopicAs.title`）
以前都要内部编号。编号在结果里出现、参数表又要编号，模型就拿去当句柄用；编号对不上时只能翻磁盘。
这一版把这三处都改成抄标题：

- `memory_save.updateTitle`：给原样标题就更新那一条；没有这条记忆时直接说明，不静默新建。
- `memory_save.links[].title`：按标题解析成内部 id 再落盘，标题对不上就拒写，不写半条。
- `memory_save.sameTopicAs {scope, title}`：绑到同层某条的主题槽位，不再要 revision。
- 参数表里不再出现 `id`、`mem_` 形态的字段；`supersedes` 也只收标题（旧调用传 id 仍认）。

## 召回排序：标题里两个独立概念同时命中，加权

「本机凭据位置：npm 发布与 GitHub 推送」这类规则标题里带着查询的两个不同实词，
以前只按「命中一个词」记一次分，容易和无关条目同分，按上限截断时被挤掉。
`view.matchScore` 增加 coverage 项（1.6 分）：标题/别名里命中的不同实词 ≥ 2 时加分，
同分情况明显减少；通用词仍按语料 df 降权，不靠「文件」「项目」这种词刷分。

## 兼容

- 存储形态不变（关联仍存内部 id），读正文、关联读取、面板访问范围不变。
- 默认召回上限仍是 3 条 / 1200 字节，阈值不变；这次只改排序，不放开闸门。
