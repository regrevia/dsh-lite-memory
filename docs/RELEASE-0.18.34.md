# 0.18.34：学到的东西能落下来，续句和审批算同一件事

- 首次在空项目里学到的规则不再因为“任务范围不在本项目”整条作废：收集时的任务范围被信任并原样保留，模型自己编的范围仍要校验。
- 条件按 key 唯一合并：同一个条件键两个值明确判冲突，不再先写成 active、再发现不适用；收集时的阶段只作上下文，不混进适用范围。
- 待裁决另存不再丢 `selection`、`triggers`、`links`：草稿审阅看到的就是最终会写下的内容。
- 任务身份独立于召回快照：正常轮次结束后的“继续”仍接上一次任务；上一轮零召回时，“继续”也不会把更早的记忆带回来。
- 历史线索以任务起始消息为边界：只补本任务内发生的动作，不把上一个任务的工具调用当线索。
- 工具动作后最多补查一次，且和首次召回共用一个请求额度。
- 真正交付给模型的卡片才更新 `lastUsed`：准备阶段被丢弃、超出预算、已过期的卡片不再算“用过”。
- 生命周期先于主题裁决：过期/被取代的条目不再参与同主题分组，不能把现行条目标成冲突。
- 审批原子化：待裁决的版本检查、另存、出队在同一临界区；旧面板不能批准新草稿，也不能删掉刚更新的待裁决。
