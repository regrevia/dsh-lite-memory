# 0.18.43：回执上限从 256 降到 64

## 问题

回执只用于同一 `operationId` 的重放保护，重试都发生在当下；按 7 天 TTL 叠加 256 条
上限，热点层实测单层回执 35 KB。面板并不读这份列表，`state.receipts` 纯粹是防重
数据，留 256 条等于白占状态体积。

## 改法

- `LIMITS.receipts` 256 → 64。仍按 7 天 TTL 过期，仍在每次状态写入时清理。
- 单个热点层实测回执体积从 35.7 KB 降到约 9 KB；重放窗口覆盖当下重试与并发收尾，
  不涉及历史查询。

## 验证

- 全量 `npm test` 通过（含回执过期清理、按 `operationId` 重放两条回归）。
- 线上层 `DSH-0ea3b310` 下一次写入即截到 64 条。
