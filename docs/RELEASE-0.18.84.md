# 0.18.84：合并判据看方向，检索先定档

这一版把「记什么」和「查多深」各自收口一层，没有加新页面。

## 自动合并：只看旧知识有没有被留住
- 判据从双向相似改成方向覆盖：新正文要留住旧正文 88% 的片段才算同一段知识。追加式更新（老内容原样保留、只在后面补一句）因此能自动合并，不必再走人工裁决。
- 双向相似度仍作子集守卫：短正文只覆盖长正文一部分时进待裁决，不会悄悄删掉旧内容。
- 正文比旧正文缩水超过一成，仍视为改写而不是重存，一律留给人。

## 检索调度器（新 `scheduler.js`）
- 本地确定性规则判七类查询：报错排查、操作流程、精确查找、接着上文、方案规划、生成写作、一般。优先级让具体任务压过宽泛词——「写一段发版说明」判生成，「发版前要做什么」判流程。
- 三档预算：低档候选 4 / 卡片 1 / 400 B，中档 8 / 2 / 800 B，高档 12 / 3 / 1200 B。1200 B 与 3 张卡仍是投递端硬上限，调度器只能往小了收。
- 接在自动召回上：先按这一轮的话定档，再决定候选深度与装几张卡；召回回执新增 `plan`（类型、档位、候选数、卡片数），只记判断不记用户原话，面板能回答「这次为什么只提醒一条」。
- 调度器不 import 任何内部模块，不读文件不联网，方便离线回放同一套规则。

## 修正
- 待裁决区不再整块只读：能否「另存一条 / 丢掉」改成逐行判（记忆开关关掉、或这行属于别的项目才不可点），选中别的层不再把整块锁死；跨项目只读复用同一判据，不并列两套写法。
- 预算拒绝真生效：自动召回按「拼上这一张后的完整文本」逐张准入，装不下就少给，不再先按计数放行再整段清零；删掉与准入重复的二次清零分支。
