# 0.18.10：编号不再出现在任何看得见的地方

## 编号只留作底层实现

0.18.9 把更新、关联、同主题的句柄换成了标题，但编号还会从别处漏出来：保存结果、搜索结构化结果、
召回卡片、面板引用、撤销回执、读正文回执。这一版把这些出口全部收口，模型和面板只看得到标题、
范围、版本号：

- 工具返回与结构化结果（`presentationMeta`、搜索 `refs`）不再带 `id`；`refs` 用标题、范围、类型表达。
- 召回卡片只带标题、范围、版本；面板引用按 `范围 + 标题 + 暴露位置` 去重，不再依赖编号。
- 撤销回执只回标题、版本、结果（`restored` / `archived`）；撤销请求本身也只收标题 + 版本。
- 读正文回执不再带 `id`；面板按标题读正文，`sessionId` / `cwd` / `scopeKey` 的可见范围不变。
- 兼容：旧的 `args.id` 调用仍能解析（内部路径），但任何结果都不回显编号；参数表里没有编号字段。

## 为什么必须收干净

编号一旦在结果里出现，模型就会把它当句柄复用；参数表不再收编号时，它只能去翻 `state.json`，
既费 token 又容易读错层。把编号从「结果」和「参数」两侧同时拿掉，标题成为唯一对外句柄，
模型就没有理由再碰磁盘。

## 验证

- `npm test` 全绿：契约、召回、面板、跨层、记忆管理、安全与 HA 用例都按标题断言。
- 自动召回、手动搜索、读正文、关联读取共用同一套任务上下文、适用条件与词法规则；
  条件未确认的条目仍不会被自动注入，但按标题显式读取会返回正文并标注 `needs_context`。
