# 8 小时打磨路线（2026-10-27 起）

口径截至 2026-11-10 / 0.18.86。数字以 `docs/BENCH.md` 与 `bench/bundle-baseline.json` 为准，旧轮次数字不留在这里。

目标不是加功能，是把已有能力做到成熟：轻量、低打扰、自进化、高可用、可读。

## 验收基线（每批）

- `npm test` 全绿；新增行为必须有回归测试。
- 写入质量：超单条上限（4096 B）回 `needsCompaction` + `stored:false` + `maxBytes` + 可执行拆法，不谎报成功；软提示（细节较多 / 引用临时路径 / 建议补适用条件）只随回执给一行，不拦写入、不改正文。
- `client.js` 体积棘轮：实测 raw 193851 B / gzip -9 49180 B（`test/bundle.test.mjs` 只许下降，基线在 `bench/bundle-baseline.json`）。40 KiB 目标（40960 B）当前还差 8220 B，是待还的债，不是达标。
- 规模基线 200/400/1000（每层条数）三档全 gate，数字与改动理由记在 `docs/BENCH.md`（0.18.86 实测）：
  端到端 400 条 P95 106.1 ms / 800 条 P95 156.7 ms / 2000 条 P95 347.5 ms，注入 263 B；纯召回 `npm run bench:scale` 400→21.9 / 1000→53.1 / 2000→109.6 / 5000→278.7 ms（P95，5000 档超 250 ms 目标，原因与取舍在 `docs/BENCH.md`）；召回上限随条数放宽（150 ms→400 ms 封顶）。
- 召回质量：`node bench/recall-quality.mjs` 报 39 条冻结样本的 Recall@3 / MRR@3 / 误注入率 / 拒答准确率 / 平均注入字节 / P50·P95（当前 1.000 / 1.000 / 0.000 / 1.000 / 151 B / 0.77·1.06 ms），
  阈值与 `test/eval-seed.test.mjs` 同源（Recall@3 ≥ 0.9、误注入 0、条件未知不投递），样本只在 `test/recall-eval-fixtures.mjs` 维护一份。
- 数字按整段比（`view.matchScore` 的 `number` 加分）：「条目 7」不再和「条目 77/797」并列靠 id 决胜负。
- UI 改动：改前/改后截图、深浅主题、窄宽两档；四条 lint error 为 0。
- 不碰 `~/.dsh/lite-memory` 真实数据；预览全部假数据。
- 不把展示层状态写进学习状态；关闭记忆后宫殿仍可只读浏览。

## R1 可读性

- 对话引用三层：搜索命中 / 读过正文 / 本轮更新；类型、来源、状态、版次用层级与语义色区分，正文仍最重。
- 面板：头部压缩、列表密度、选中态、长标题、空/加载/错误三态。
- 宫殿：房间宽高由内容决定，去掉无意义空地；槽位可读、分页清楚、详情复用。

## R2 规范

- 触发：明确「自动注入 / 仅可搜索 / 静默」三态与原因码，避免误触发和重复打扰。
- 更新：替换、撤销、冲突、版本、证据继承的边界写进测试与文档。
- 记录：审计字段、失败恢复、用户可见原因；不泄漏内部实现词。

## R3 高可用

## 下一阶段优先级（2026-11-10 评估结论）

方向从「能记住多少」转到「什么时候该记住 / 该调用 / 绝不能调用」，不加向量库、不加知识图谱、不加后台反思服务。

- P0 评测闭环：把已冻结的两套样本（`eval-seed` 39 条、`eval-hard` 30 条）的数字固定下来；缺的是每轮报得出 Recall@3、Precision@3、误注入率、拒答准确率、注入字节、P50/P95，而不是再写新断言。误注入比漏召回罚得重。
- P1 规模成本：端到端与纯召回已分开量（`npm run bench` / `npm run bench:scale`）。纯召回 5000 条 P95 278.7 ms 超目标，瓶颈是每次 `rank` 全量统计词频 + 逐条打分；要不要上轻量倒排索引，取决于 5000 条是否为真实规模。索引只能从主数据重建，不能成为唯一数据源，不能引外部服务。
- P1 生命周期：确认失效记忆不会再经由旧别名、历史索引回到默认召回；撤销与删除要清派生引用。
- P2 明确拒答（abstain）：区分「不适用 / 已失效 / 与当前规则冲突 / 曾被否定 / 证据不足」，证据不足时宁可沉默。
- 暂不做：完整向量库、完整图谱引擎、每轮自动反思、无上限自动记忆、自主改检索算法、复杂遗忘评分。

## 已知未做（有判断，没动手）

- 价值裁决的半衰期加权：结论上应该按「这条帮到过」的时间衰减排序，只在同分时用它裁决。但现在能观测的只有 `hits`（被投递）和 `used`（被读过），两者都不等于有用，也没有「帮到了」的反馈通道；硬做就是把「被读」当「有用」，长文档会越排越前。等出现可归因信号（例如模型在回答里标明用了哪条）再补，不拿 `lastUsed` 顶替。
- `memory_save` 的 `presentationMeta.mode` 不加 `needs_compaction`：硬上限已由 `stored:false` + `needsCompaction` + `maxBytes` + 拆法 + 回执正文说清楚，而 `mode` 目前没有消费者（客户端只看 `changed` 和回执行），多一个枚举值只是多一层表面。
- 混合主题软提示只看小标题数（≥3 个二级/三级标题）；没有小标题的杂糅正文不猜，宁可不提示也不误报。
