# 0.18.11：普通记忆也能在面板里改

## 只开一条最小写入口

0.18.10 之前，面板只能改实验规则；普通记忆能读、能归档，正文写错了只能让模型再保存一次。
这一版在记忆面板的当前项目里加「修改」：就地改标题和正文，保存后版本加一，标签、类型、
适用条件、关联和学习状态都不动。

写入口只有一条：`POST /lite-memory/entry`，复用 `saveEntry` 的记录分支，不新增改记忆的函数。

- 必须带面板读到的 `expectedRevision`；写前在锁内再比一次，中间被别人改过就 409，
  回包标 `retry: true`。面板把最新正文和版本取回来，草稿留在输入框里，确认后再存一次。
- 改名不能撞上另一条现行记忆：标题是唯一句柄，撞了以后按标题读会分不清，直接拒绝并指出同名条目。
- 只写当前会话确认过的项目层。别的项目、全局层一律 409；项目切换、目录未确认、记忆关闭都拒绝。
- 回执只给标题和版本，不给编号。

## 层与锁的边界收紧

- 显式 `scope="project"` / `scope="global"` 只解析和写那一层：读取、关联、归档、彻底删除都
  不再回落到另一层。同名条目在两层都有时，必须点层，不能靠「先找到哪条」决定。
- 保存只锁真正要写的那一层（新增按归属路由，更新按条目所在层）；两个项目各写自己的条目时
  不再因为共享全局锁互相等待。全局写仍然锁全局层。
- 「以后所有口播」「以后一律」这类覆盖全部对象的说法，在项目层按 `all_in_scope` 收集；
  「以后都」仍然不等于「所有项目」，不会自动升到全局层。

## 为什么不是「编辑一切」

跨项目、跨层的写权限不能从「面板能看见」推出来，也不能从模型的意图推出来；这次只放开
当前项目这一层，别层保持只读。改的是人明确选中的那一条，范围不重算、不迁移、不顺手改学习状态。

## 参数清单只做到「改正文」

标签、类型、适用条件、关联这些参数仍不在面板里改：它们影响适用性判断，逐项开放会把
「改一个标签」变成「改一条规则算不算适用」的权限问题。当前路径是：正文和标题可以就地
refine；要改参数，由模型按同标题再存一次，改动会升版本并留记录。把整条记忆转成「资料」
（保留原文、按需读取、不默认注入）需要独立的资料存储与删除/导出闭环，留到下一版，不在这
一版假装已经支持。

## 验证

- `npm test` 全绿。
- 契约用例覆盖：正常改正文并升版本、旧版本写入被拒、样式/标签保持、改名撞车被拒、
  别项目与全局层被拒、空标题被拒；面板点开正文前后状态文件逐字节不变。
- 边界回归覆盖：被取代和已过期的条目不会进入自动注入，也不进默认检索；只有显式查历史才看得到。
- 宫殿回归覆盖：点展品只把条目交给详情入口，不改宫殿里的记录；浏览不写状态。
- 边界新增：显式项目层读不到、也彻底删不掉全局唯一条目，且全局条目原样保留；另一个项目
  占着全局锁时，本项目保存自己的条目照常成功；刚存完立刻检索命中的是刚存的那一条。
- `ui-copy-lint` / `zh-lint` / `style-lint` 无新增错误。
