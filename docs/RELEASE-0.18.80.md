# 0.18.80 — 同一段知识存两次时先自己并掉，不再一律等人定夺

## 现象

面板「待裁决」里长期压着 3 条，其中两条是同一份流程写了两遍：

| 待裁决 | 标题 | 时间 |
| --- | --- | --- |
| 1 | 发版取凭据：npm token 在 Keychain，GitHub 用 gh | 2026-10-28 06:15 |
| 2 | DSH 插件改动的生效验证顺序（桌面端 ⌘R 会走 unlag reload） | 2026-10-28 12:06 |
| 3 | ……（含：桌面端没有 Cmd+R） | 2026-10-28 12:06 |

第 2、3 条正文几乎逐字相同，第 3 条只是多了「旧说法作废」这句更正。系统早就能算出它们相近
（`similar_title` / `similar_summary`），却只会停下来问人，所以这类明显重复也要用户一条条点。

## 修法

`saveEntry` 撞上相近条目时，在排队之前先自己判一次（`store.js`）：

- 只认**唯一一条**相近条目、**同一层**、两边正文都非空；
- 正文按去空格标点后的四字片段算重合度（`bodyOverlap`），达到 `SAME_KNOWLEDGE = 0.88` 才算同一段知识；
- 新正文不能比旧正文短（除非重合度 ≥ 0.98），否则可能是把旧版本重存，并进去会丢内容；
- 判定成立就按 `expectedRevision` 回写那一条：仍然只有一条记忆，旧正文留在版本历史里（`versions` 可撤回），
  顺手清掉同标题的待裁决；
- 回写只重放正文与语义字段，草稿里的「取代 / 改标题」指令不跟着重放；任何异常、不相近、多条相近、
  跨层相近，全都退回原来的待裁决队列——不猜。

工具结果补一句 `hints`：「正文和已有的一条几乎相同，已并进那条（旧正文留在版本里）」，模型不会误以为又加了一条。

## 验证

`test/store.test.mjs` 新增 2 条：

- 同一段知识存两次 → `needsResolution false`、`autoMerged true`、条目仍 1 条、待裁决 0 条、
  新正文（含「作废」）落到那条上、`versions` 1 份；
- 只是标题像、正文不同 → 仍然 `needsResolution true`、待裁决 1 条（不替人猜）。

`node --test test/*.mjs`：52 passed / 0 failed。`node --check store.js index.js` 全过。
