# 「记住我」与检索算法升级：设计与开发方案

基线：本仓库 `0.18.51`（提交 `6d398a8`）。本方案只改 `dsh-lite-memory`，不引入服务端、向量库、常驻模型或后台 Agent。

## 结论

- 可行。差异化不在「有用户画像」——Honcho 已有 DSH 插件——而在**慢、小、可纠正、按需投影**。
- 检索增强先做本地排序与预算内的组合选择，零新增模型调用。
- 「记住我」默认关闭，独立存储、独立开关、独立选择器，绝不进入普通记忆的检索/搬层/链接路径。
- 直接复用竞品的是**数据结构与写入纪律**，不是它们的服务栈。许可证要按文件核：Honcho 核心 AGPL-3.0，其 DSH 插件 MIT，不可混谈。

## 一、算法升级（先做，收益最快、风险最低）

### A1 多路候选 + RRF（只影响排序，不放宽资格）

候选通道：词面命中、已生效别名/触发词、当前任务的可靠对象与动作线索、已命中条目的一跳显式关联。
每一路都要**独立**过现有的资格（项目、条件、有效期、对象相关性）；链接不继承源条目的通行证。
融合只用排名：`score = Σ 1/(k + rank_i)`，`k=60`。零候选仍返回空，不做保底填充。

### A2 预算内组合选择（替代「各自打分取前 3」）

取最多 12 个合格候选，枚举 0–3 项组合（299 种），按真实渲染字节校验后综合：任务相关性、信息覆盖、重复度、是否挤掉更高优先级的项目规则。
产出单一函数 `selectContextBundle(candidates, {maxItems, maxBytes, allowEmpty})`，普通卡片、自进化规则、画像投影共用，不再各加一份预算。

### A3 受限的检索自进化

只允许由**真实漏召回/误召回反馈**触发一个最小改动（加一个别名 / 调一个权重 / 修一处重复关系），在冻结回放集上验证后才能生效；必须有参数 diff 与回滚。
禁止自进化触碰：项目隔离、全局授权、开关语义、条件未知时的放行、预算上限、用户当前明确要求。

## 二、「记住我」的产品定义

三块信息严格分开：

| 模块 | 回答的问题 | 存什么 |
| --- | --- | --- |
| 项目记忆 / 项目自进化 | 这个项目怎么做 | 项目约定、适用条件、已验证经验 |
| 普通全局记忆 | 哪些经验跨项目成立 | 经确认的通用方法 |
| 记住我 | 怎样和你协作更顺 | 少量、抽象、长期的协作偏好 |

首版固定 8 个闭集维度：`answer_order`（结论先行）、`explanation_depth`、`example_use`、`option_presentation`、`option_count`、`tone`、`progress_updates`、`comparison_format`。每维允许 `unknown` / `insufficient` / `contextual`。

不进入画像：一次催促→「性子急」；一次要详细→「永远要长答案」；某项目要白色细线→「所有作品极简白」；用户自己说话短→「回复也要短」。**用户怎么表达 ≠ 用户希望被怎么回应。**

## 三、学习算法

1. 每轮本地筛信号，不调模型：只认对表达/协作方式的明确反馈或选择。
2. 攒够再学：新增 ≥6 条待查片段、距上次整理 ≥24h、项目记忆与「记住我」都开、有学习预算、无更高优先级任务。
3. 抽取器只输出结构化观察：

```json
{ "observations": [{ "dimension": "answer_order", "value": "conclusion_first",
  "polarity": "support", "evidenceIds": ["e17"], "basis": "explicit_feedback" }] }
```

无 `personality`、`systemInstruction`、自由文本字段。

4. 证据去重按「用户 × 会话/任务 × 日期 × 维度 × 事件」：同一任务重复催促最多算 1 份，单个项目不得贡献全部支持。
5. 成熟度用保守后验 + 硬门槛：跨度 ≥14 天、独立观察 ≥8、覆盖 ≥4 个日期、≥2 类情境、最近明确反对则不成立、最多每 72h 形成/改变 1 维。
6. 明确反对立即停用该维度，并记原因；人工修改优先于推断。
7. 反自我证明：画像被召回、用户没反对、用户说「继续」、助手按画像写过回答，都不是支持证据；情绪强度不加票。

## 四、读取与投影

- 专用 `selectPreferenceProjection({currentRequest, outputMode, explicitRequirements, formed})`，只选与交付形式相关的维度；严格 JSON/固定模板/逐字翻译时不投影。
- 本轮用户明确要求压过历史偏好。
- 最多 1–2 维、一个块、渲染后 ≤200 字节，与普通记忆共用 3 项 / 1200 字节上限；无预算就不放，不截断半句。
- 画像只影响表达方式，不得改变技术路线、参数、权限、发布/删除决定、事实可信度或是否验证。
- 跨项目聚合只接触闭集枚举与带来源编号的计数，不读其他项目正文/代码/指令。

## 五、开关与面板

开关名「记住我」，说明：缓慢学习你的交流与协作偏好，逐渐形成少量长期理解。默认关闭，可能增加少量模型用量。项目记忆关闭时，本项目不使用也不参与学习。

| 项目记忆 | 自进化 | 记住我 | 行为 |
| --- | --- | --- | --- |
| 关 | 任意 | 任意 | 不读/不采/不学 |
| 开 | 关 | 关 | 只有普通记忆 |
| 开 | 开 | 关 | 只演化项目规则 |
| 开 | 关 | 开 | 只学协作偏好 |
| 开 | 开 | 开 | 两条路径各守边界，共享预算 |

关闭时：停止采集与投影、取消在途任务、轮换同意代次、保留已有画像、重开不补跑。`tool_only` 下自动投影与采集一起暂停。

面板三块：已形成（每条附来源概况）、观察中（真实进度：「已观察到 3 次，仍不足以判断是否长期」）、最近变化（哪维变了、为什么、是否自动、是否用过）。动作：符合我 / 不符合 / 暂停使用 / 删除。不做人格雷达图，面板按需挂载。

## 六、代码结构

- `persona.js`（纯逻辑）：`detectPreferenceSignal` / `validateObservation` / `deduplicateEvidence` / `updateEvidence` / `decideMaturity` / `selectPreferenceProjection` / `renderPreferenceProjection`。无网络、无文件、不读其他项目。
- `persona-store.js`：`readPersona` / `setPersonaEnabled` / `beginPersonaAttempt` / `commitPersonaObservation` / `editPersonaPreference` / `rejectPersonaPreference` / `retractPersonaEvidence` / `clearPersona`。用户身份取宿主可信身份，不接受模型传 userId。
- 画像文件独立存放，排除于项目枚举、`memory_search`、`memory_read`、链接与搬层之外。
- `index.js` 只编排：请求开始取身份→门控→投影→统一准入；回合结束按需排队；提交前再核验。

提交必须原子校验：`sourceProjectControlEpoch`、`personaConsentEpoch`、`personaRevision`、`sourceEvidenceGeneration`、`sourceEventId`。入口检查过不算数——模型跑十秒后用户关了开关，结果不得落盘。

状态骨架：

```json
{ "schemaVersion": 1, "control": { "enabled": false, "consentEpoch": "..." },
  "revision": 4,
  "preferences": { "answer_order": { "value": "conclusion_first", "state": "formed",
    "source": "inferred", "support": 8, "opposition": 0, "distinctDays": 5,
    "contexts": 3, "firstSeenAt": "...", "lastSupportedAt": "...", "lockedByUser": false } },
  "evidence": [], "recentChanges": [], "blockedDimensions": [] }
```

`evidence` / `recentChanges` 有界；硬上限 64 KiB。长期无新证据不等于反对，只降权并标待复核；用户确认过的偏好不因久未触发被静默删除。

## 七、开发顺序

1. **PR 1 共同边界**（前置，先清干净）：空整理结果保持无变化、否定/引用不写成规则、重复合并也做版本校验、所有自动内容走统一资格与预算、跨层提交校验真实来源项目与开关。验收＝上一轮复现问题全部进回归。
2. **PR 2 本地检索**：有界候选融合、重复压缩、预算内组合选择、空结果、召回原因。验收＝同预算、零新增模型调用，改写召回变好且负例不恶化。
3. **PR 3 开关与存储**：默认关闭、身份隔离、闭集维度、人工确认/暂停/清除、原子提交与在途失效、面板空态。验收＝没有自动学习也能完整用、能关、能清。
4. **PR 4 慢学习**：本地筛信号、有界批处理、结构化观察、证据去重、成熟度、反对即停、真实 token 记录。
5. **PR 5 按需投影**：本轮要求优先、只选相关维度、共用预算、不写会话历史、更新/关闭/删除即失效。
6. **PR 6 检索自进化**：可信反馈、单点改动、冻结回放、diff 与回滚、禁改边界。

## 八、验收用例（首版必须全过）

1. 单项目连续 20 次要求同一风格，不升成跨项目偏好。
2. 用户引用别人的习惯，不学成自己的。
3. 一次情绪化表达不生成性格标签。
4. 跨 14 天、多情境的稳定反馈可以形成 1 维偏好。
5. 本轮要求「详细」，历史「简洁」不缩短必要内容。
6. 关闭项目记忆后，画像也不参与。
7. 人工修正后，晚到的模型结果不覆盖。
8. 删除画像后，旧事件不使其复活。
9. 加入大量无关记忆后，投影体积不增长。
10. 长期模拟后维度数仍有界，变化体现为旧维度更准，而非条目更多。

时间与并发在测试里模拟；「更少重复纠正」只能用数周真实使用验证，不做单轮演示式宣称。

## 九、成本与诚实边界

- 本地存储 ≠ 全本地计算：整理若用宿主云端模型，选中的少量片段仍会发给该服务。
- 写进请求的画像块，宿主每多一次模型调用就可能再计一次输入 token；因此同时记「整理调用 token」与「每次请求实际携带的画像字节」。
- 每用户滚动 24h 自动整理 ≤1 次；单次输入 ≤4096 字节、输出 ≤256 tokens；单次最多更新 1 维。
- 能验证的是：插件没把项目事实通过画像通道送出去、本轮要求能压过偏好、错偏好能停用；不能承诺语言模型绝不跑偏。
