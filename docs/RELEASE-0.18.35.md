# 0.18.35：召回账本能对上，跨项目写入要人点头

- npm 原生凭据命令在执行前拦一次：`npm whoami` / `publish` / `login` / `token` / `config get` 会直接收到已有记忆里那条「发布一律走 dsh-npm」的正文，同一请求只提示一次，`dsh-npm` 自己的命令不受影响。
- 自动注入只有一份预算：普通卡片与实验规则合计最多 3 条、1200 字节，按整条准入；最终交付文本的字节数和卡片数与账本一致，准备阶段被丢弃、到期撤下的条目不再记使用。
- 任务状态和展示快照分开：第一步零命中不再丢掉请求身份；之后只有真正的执行动作（写文件、跑命令等）触发一次补查，读文件、`memory_search`/`memory_read` 的输出不花这次机会；换任务后旧动作线索不跟过来。
- 使用记账推迟到回合收尾批量写，provider 输出路径不碰写锁；回合结束、请求替换和 agent 销毁都不会漏掉最后一轮的使用记录。
- 跨项目写入只认真人原话：模型写进 `memory_save` 参数里的 `scope` 只是提案，自动整理产物一律留在项目层；只有本轮明确说「存到全局/所有项目/跨项目」才允许落全局，普通说「全局变量」不会误判成授权。
- 学习条件统一校验：收集阶段带进来的 `taskKind` / `seriesId` 是可信范围，模型新提的条件仍要落在本项目已有栏目或阶段里；同一主题连续纠正收敛到一条现行版，换栏目不适用，关掉再开还是同一现行版。
- 基准改成真实的跨层召回：200 条项目记忆 + 200 条可信全局记忆，加一条正面场景，确认全局卡片确实进得来且不超预算。

验证：`npm test` 全绿；`npm run bench` 在本机固定数据集上通过。
