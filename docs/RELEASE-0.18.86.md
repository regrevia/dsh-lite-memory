# 0.18.86：分类边界修词形，回放与生产同源装箱

这一版不加功能，只修两处已有判断的口径：调度器认词形、回放认档位。

## 分类边界（`scheduler.js`）

- 英文词形按整词认，不再吃前缀：`copyright` 不再被判成「内容生成」，`crashes / errors / bugs`、`planning / refactor(ed|ing)`、`summarized / translated / drafted / written` 都能命中各自类型。
- 中文规则与先后顺序不变：排障 > 精确查找 > 规划 > 生成 > 流程 > 续接；「继续评估重构方案」仍是规划，「解释为什么要写发布说明」仍是流程，「继续」单独出现才是续接。
- 空查询仍返回 `general`（0.18.84 起），这一版没有改回续接。
- 新增 50 条表驱动回归（`test/scheduler.test.mjs`），覆盖三种档位的正反例、纯续句与带目标续句的边界、空输入、英文词形误判。

## 回放与生产同源装箱（`evolve.js`）

回放此前用 `CARD.max / CARD.bytes`（3 张 / 1200 B）装箱，而生产已按档位收口，低档回合两者会得到不同卡片集合。现在回放先按这一轮的话定档，再用 `min(硬顶, 档位额度)` 装箱，`deliveredIds` 与 `budgetDropped` 的口径与生产一致；排序参数、适用性门槛不变，回放仍只求两轮可比。

## 三档规模重测（`docs/BENCH.md`）

同机重跑 200 / 400 / 1000（每层）三档，数值已写回 `docs/BENCH.md`：P50 91.2 / 145.7 / 323.4 ms，P95 106.1 / 156.7 / 347.5 ms。与 10 月 31 日那组相比，1000 档 P50 +15.1 ms、P95 +20.5 ms，属于同机日内波动量级；调度定档是纯本地正则，没有新增 IO、缓存或额外扫描，本轮不据此做优化。

## 回执账单与面板判断结果（`index.js` / `client.js`）

- 回执 `plan` 多记一个 `dropped`：档位字节装不下、准入被拒都算淘汰，面板能说清「为什么只投了这么几条」。
- 回执的 `bytes` 改按这一轮的档位落账（低 400 / 中 800 / 高 1200），不再统一记满 1200 B；回放与生产读同一份账单。
- 面板回执多一行判断结果：`排障 · 深入 · 候选 12 · 投递 3 · 使用 1200 B`。只显示中文标签，不出现原始枚举和内部原因码；旧回执没有 `plan` 时只显示原来的条数，不报错。

## 旧库维护信息不再丢（`state.js`）

`toStateEntry` 重建条目时漏了把旧 `maintenance` 原样带过来，固定住的规则（`maintenance.learning.pinned`）在收编后会变成可腾挪的普通条目，容量腾挪时被归档。现在先整份继承旧维护信息再补默认值；`test/store.test.mjs` 补了一条回归：把修复回退即失败。

## 读不到东西就一种说法（`client.js`）

- 记忆、自进化、记住我三处占位各自拼一遍「加载中／失败原因／重试」，同一个状态在不同地方说成两句话，读失败时还留着空列表。收成一个 `loadingCopy`，三处共用：读取中只说读取中，读完没成功一定给原因，并一定给「重试」。
- `load()` 成功判据从「HTTP 过了且 `body.ok` 真」改成 `succeeded(result)`：2xx 但 `ok:false` 以前被当成成功，界面停在空白列表上；现在按失败显示原因和重试。
- 待裁决逐条处理只发这一行自己的 `scopeKey`：合并视图里选中的是「所有项目」，以前会把它当目标范围发给服务端，被 400／409 挡回来。
- 面板里 9 处竖排字段、7 处横排一行的样式字面量收成 `COL4` / `ROW8` 两份常量。
- 包体：`client.js` raw 193851 B、gzip -9 49180 B，距 40 KiB 目标 8220 B。原始体积比上一版小 90 B，但重复串被压缩器白吃的那部分没了、加上新的占位文案，gzip 升 331 B，基线显式上调并写清原因，差额继续记为待还的债。
- 回归：`test/client.test.mjs` 24 项通过（含 `loadingCopy` 三种状态与失败透传）；全量 35 个测试文件 exit 0；`ui-copy-lint` 新增 0 error、`zh-lint` 0 error、`style-lint` 0 error。
